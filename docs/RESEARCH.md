# Research pipeline and data quality

## Flow
1. **Discover** (optional): Admin → Research jobs → *Discover sources*, or `npm run research:discover -- nike tshirt MEN`.
   Uses a permitted search API; results are filtered to the allow-list and classified (brand size guide, brand product page, marketplace listing). Nothing is fetched at this step.
2. **Fetch + extract**: a job (max 5 URLs) fetches each allow-listed https URL politely (robots.txt, 8 s / 2 MB limits, redirects re-validated, DNS must be public, 401/403/429/CAPTCHA reported as ACCESS_RESTRICTED and never bypassed). Adapters read HTML tables or listing text.
3. **Interpret, never guess**:
   - *Unit*: column label, then a statement on the page (“measurements are in cm”), else `UNKNOWN` → not converted, not imported.
   - *Meaning*: only what the page states (“body measurements”, “garment measurements”). Otherwise `UNKNOWN`; each dimension AMBIGUOUS.
   - *Cut*: stated fit (“slim fit”) or the admin’s target hint, else `UNKNOWN`.
   - Open-ended cells (`<31`, `51+`) drop that size; bounds are never invented.
4. **Validate**: plausibility ranges, increasing sizes, duplicates. Errors → INVALID_DATA (nothing stored); warnings → NEEDS_HUMAN_VERIFICATION.
5. **Store**: a new chart version (UNVERIFIED or NEEDS_HUMAN_VERIFICATION). Identical data is detected and not duplicated. Each source is logged per job.
6. **Verify (a person)**: Admin → Source verification. Open the source, compare rows, resolve meaning per dimension (body/garment, circumference/linear, or flat width with explicit ×2 conversion), approve or reject with a reason. Only VERIFIED and UNVERIFIED charts are used for recommendations; UNVERIFIED results are provisional.

PDF guides are not parsed automatically: the job says so; copy the table and use the CSV importer.

## Search providers
| Provider | Env vars |
|---|---|
| Brave Search API | `SEARCH_PROVIDER=brave`, `BRAVE_SEARCH_API_KEY` |
| Google Programmable Search | `SEARCH_PROVIDER=google`, `GOOGLE_CSE_API_KEY`, `GOOGLE_CSE_ID` |

Respect each provider’s terms and quotas. Adding a domain to research requires adding it to `ALLOWED_RESEARCH_DOMAINS` (and an adapter) in code, reviewed like any other change.

## Statuses
Research outcome: SUCCESS, PARTIAL_SUCCESS, SOURCE_UNAVAILABLE, ACCESS_RESTRICTED, INVALID_DATA, NEEDS_HUMAN_VERIFICATION.
Chart version: VERIFIED, UNVERIFIED, NEEDS_HUMAN_VERIFICATION, INVALID, DEPRECATED.

## Coverage
Admin → Data quality shows brand × category × gender coverage, missing brand-level vs product-level notes, products without charts, and automatic checks. File reports are regenerated by `npm run research:csv` into `prisma/data/research/reports/`.

## Target brands and marketplaces
Brands: Zara, H&M, Uniqlo, Levi’s, Nike, Adidas, Puma, Bewakoof, Snitch, The Souled Store, Max Fashion, Westside, Savana (+ Arbour, found via a Flipkart listing). Marketplaces: Myntra, Flipkart, Nykaa Man (Nykaa Fashion is allow-listed for discovery). Marketplaces are never brands; each listing belongs to its product’s real brand.

Current coverage is what `prisma/data/charts.json` holds (Nike tops; three product charts). V5 did not add charts: the build environment had no access to brand sites, and FITSYNC does not fabricate data.
