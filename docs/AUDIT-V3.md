# FITSYNC V3 audit (done before implementation)

Scope: package.json, Prisma schema + migrations, seed, charts.json, engine, CSV parser, admin, auth, API routes, components, brand explorer, comparison, tests, CI, Vercel config, README.

| # | Area | Finding | Status in V3 |
|---|---|---|---|
| 1 | Missing features | No marketplace/product/listing model, so marketplace data could not keep its brand identity. No research pipeline, no audit trail of verification, no research jobs. | **Added** (migration `20261110000000_v3_research_products`, `src/lib/research`, admin tabs) |
| 2 | DB relationships | Brand-level uniqueness used a nullable column pattern that would allow duplicate brand charts once products exist. `BrandSizeChartVersion.verifiedById` and `BrandCoverageNote.categoryId` are plain strings, not foreign keys. `Recommendation → chartVersion` is RESTRICT, so a version used by a recommendation can't be deleted (intentional, versions are deprecated instead). | Uniqueness **fixed** with `productKey`. The two string ids are **open** (low risk, documented). |
| 3 | Incomplete brand data | Only Nike had official charts. 11 target brands had none. | Research re-run in V3: Nike women's chart re-confirmed (+XXS) and Nike women's Asian added; 3 product-level marketplace charts added. Zara, H&M, Uniqlo, Levi's, Adidas, Puma, Snitch, Souled Store, Max, Westside, Savana remain **DATA UNAVAILABLE** (see `research/reports/failed-research.md`). |
| 4 | Conversions | Conversion happens once, at the edges, and is now covered by round-trip tests. **Bug found:** the importer compared JSONB rows with `JSON.stringify`, but Postgres reorders keys, so re-running the seed created duplicate versions. **Bug found:** plausibility check was too loose (36 "cm" chest passed). | Both **fixed** with regression tests. Half-width/circumference is never converted automatically. |
| 5 | Engine | Heuristic score was named "confidence" (implies a probability). No notion of ambiguous measurements. Garment-only measurements (length, sleeve, rise, leg opening) had no place. Only 4 categories. Ease allowances are assumptions, not validated. | Renamed **Fit Match Score (experimental)**, `provisional` flag, ambiguous dimensions excluded, garment-only dims stored not scored, 13 categories. Ease values remain **unvalidated (open)** until real fit feedback exists. |
| 6 | Chart selection | Product charts did not exist, so no override rule. | Rule implemented and tested: verified product > verified brand > unverified product > unverified brand; another product's chart is never used. Region default is still IN > GLOBAL (no per-user region yet, **open**). |
| 7 | CSV import | Spec header `size_label`/`*_cm` was not accepted; no per-column unit; no garment-only columns. | **Fixed**, duplicate and unit-mistake detection tested. Upload size limit is 50k characters (server-side). |
| 8 | Security | In-memory rate limiter is per instance. JWT sessions can't be revoked server-side. No email verification/password reset. New risk: any URL-fetching feature = SSRF. | SSRF guard built for the pipeline (https only, allow-list, no IPs/credentials/ports, DNS must be public, every redirect re-validated, robots.txt, size/time limits, no CAPTCHA/403 bypass). The first three are **open**. |
| 9 | UI/UX | "Confidence" wording; no product selection; no way to see ambiguity; admin could only verify/deprecate. | Product selector, brand-level vs product-specific labels, provisional notice, ambiguity notices, admin Coverage/Charts/Research/Brands tabs. Not manually tested on real devices. |
| 10 | Deployment | CI had no data validation step; seed is manual after migrate. Vercel config OK. | CI now runs `research:validate`. Documented the migrate → seed → verify routine. |

What is deliberately NOT done: no data was marked VERIFIED, no brand chart was copied from a third-party site, no access control was bypassed.
